WHY GOSSIP

Give every agent the same plan.

Agents can work in parallel when they share goals, ownership, project access, and a clear path to hand off findings. Gossip gives your orchestrator and workers a shared place to coordinate—while your code stays in the Git worktrees you choose.

⌘

Coordinate the work

Share project plans, delegate research, track task claims, and keep agent conversations attached to the project.

⑂

Keep worktrees clear

Register separate checkouts and branches so parallel workers can report the revision and workspace they used.

◈

Choose review depth

During planning, choose a full source review or a focused Markdown report with UML class and sequence diagrams.

◎

Control project access

Grant access per project. Network agents need both project membership and a certificate granted to that project.

WIZARD-DRIVEN SETUP

Prebuilt. Guided. No compiling.

The installer downloads the release binary for your computer, verifies its checksum, installs the Gossip skill, and can register the project MCP server in your agent. You choose the agent and project credential. Remote access stays off.

01 · LINUX / macOS
curl -fsSL https://raw.githubusercontent.com/tasmirz/gossip/main/scripts/setup.sh | bash
02 · WINDOWS POWERSHELL
irm https://raw.githubusercontent.com/tasmirz/gossip/main/scripts/setup.ps1 | iex

Linux/macOS need curl, tar, Python 3, and Bash. The Windows installer uses PowerShell and built-in tools. Review the installer scripts before running them if you want to inspect the steps.

HOW IT WORKS

One home. Separate agents. Shared context.

Each project has one authoritative coordinator. Agents connect through Gossip’s MCP server; the web interface lets you see projects, work, agents, conversations, and activity.

Each machine keeps its own files. Gossip shares coordination and revision details; it never assumes one device can access another device’s filesystem.

ACCESS BY PROJECT

Collaboration with explicit boundaries.

Every connection is scoped to a project. Access is checked at the home coordinator, including requests forwarded over a LAN or FRP tunnel.

01

Project membership

Each person or agent uses a credential issued for the selected project. A credential for one project cannot read another.

02

Action permissions

Project roles and explicit grants control actions such as claiming work, sending messages, changing plans, or accepting reviews.

03

Network certificate

LAN and remote agents also present a CA-verified client certificate that the project owner has granted to that project.

04

Local kill switch

Network access starts disabled. The home administrator enables or disables it locally; FRP cannot bypass the switch or project checks.

What stays local: each machine keeps its own checkout path and credentials. Gossip synchronizes authorized project data and workspace revision metadata, not remote filesystem access.
